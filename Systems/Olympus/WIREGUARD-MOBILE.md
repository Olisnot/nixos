# iPhone enrollment by QR code

This extends the existing Zeus–Olympus link. Each mobile device gets its own
public peer JSON file; Zeus's key, address, routes and keepalive are unchanged.
No real phone key or QR code is generated by evaluation/building this repo.

## What the exit gateway does

- Full IPv4 internet access through Olympus, with NAT on **enp1s0**. This interface
  was verified read-only on the live VPS before implementation.
- Client DNS: `1.1.1.1` and `1.0.0.1`, routed through the tunnel. This is ordinary
  DNS, not a new recursive resolver or an encrypted-DNS service on Olympus.
- The VPS has **no IPv6 default route**. Client profiles capture `::/0` and use
  a private IPv6 tunnel address; Olympus explicitly drops IPv6 tunnel input and
  forwarding. IPv6-only destinations will not work. Dual-stack sites should
  use IPv4. This prevents ordinary IPv6 traffic bypassing the active tunnel;
  it is not an always-on iOS kill switch. Turning the VPN off restores normal
  phone networking, and iOS platform exceptions still require live checking.
- Phones can reach Olympus's TCP **80/443 only** on the host, including through
  its public IPv4. SSH, Caddy admin, and other host ports are blocked for phones
  even if the normal public firewall allows them. Public HTTPS routes remain
  inactive until explicitly configured.
- Forwarded phone traffic to Zeus, other phones, LAN/CGNAT/metadata and other
  special-use IPv4 networks is dropped. Inbound forwarding is limited to
  established replies from the public interface. Phones cannot use Olympus as
  a router into the home LAN. Zeus is not turned into a full-tunnel client.
- NAT is scoped to enrolled phone `/32` addresses, **not all of wg0**. With no
  enrolled phones, NAT/IPv4 forwarding is not enabled by this module.

The firewall uses dedicated iptables chains ahead of the normal NixOS INPUT
and FORWARD rules. It is deliberately tied to the current iptables backend;
changing to nftables requires porting and retesting this policy first. No
request/DNS/packet logging is added. Keep the firewall running: stopping it is
not a supported way to debug or maintain the VPN.

## Enrollment from Zeus

Review the source changes first. Make the new files visible to Git-backed
flakes (this does not commit or deploy):

```sh
git add flake.nix scripts/WireguardEnroll.nix scripts/WireguardEnrollCheck.nix \
  Systems/Olympus/wireguard-mobile.nix Systems/Olympus/wireguard-mobile-settings.json \
  Systems/Olympus/wireguard-mobile-check.nix Systems/Olympus/wireguard-clients
```

From the repository root, run **in a normal local terminal**, not through this
assistant or a logged remote session:

```sh
nix run .#wireguard-enroll -- iphone
```

The command creates:

- `Systems/Olympus/wireguard-clients/iphone.json`: **public key and address only**,
  suitable for source control. Default address: `10.77.0.3`.
- `~/.local/state/wireguard/olympus/iphone/iphone.conf` and `private.key` (or under
  `$XDG_STATE_HOME`): private files with mode `600`, in a mode `700` directory,
  outside the repo. Do not commit, paste, screenshot or share them.
- A terminal QR code encoding that private configuration. QR output is refused
  for non-interactive output, so it cannot accidentally enter redirected logs.

Existing device names/addresses are refused rather than overwritten. The
helper accepts only validated names and host numbers. For another device:

```sh
nix run .#wireguard-enroll -- ipad 4
```

Use a unique number **3–254**; 1 and 2 are reserved for Olympus and Zeus.
For redisplaying a code without regenerating keys:

```sh
nix run .#wireguard-enroll -- show iphone
```

The helper is also installed on Zeus after a normal local `rebuild`, making
`wireguard-enroll iphone` available directly. No sudo is needed for enrollment.
Keep terminal session recording off while displaying the code. Treat local
backups of the private state directory as containing VPN credentials.

## Deploy and scan

1. In **Hetzner's attached Cloud Firewall**, allow inbound **UDP 51820** from
   mobile/roaming IPv4 clients (`0.0.0.0/0` if arbitrary mobile networks are
   needed). A rule restricted to your home public IP will block cellular use.
   WireGuard still authenticates every peer cryptographically. Keep SSH and web
   rules unchanged. No home router port forwarding is needed.
2. Review the generated public peer JSON. Build and deploy with that file
   included (the existing `rebuild` command runs `git add .`):

   ```sh
   git add Systems/Olympus/wireguard-clients/iphone.json
   nix build .#nixosConfigurations.olympus.config.system.build.toplevel --no-link
   rebuild olympus
   ```

3. In the official iPhone WireGuard app: **+ → Create from QR code**. Scan the
   code in your local terminal, name the tunnel, and enable it after deployment.
   No private key needs to be sent to the VPS or this assistant.

The code will not give internet access until its public peer is deployed. Do
not run nixos-anywhere for this change. Expect a short wg0 restart/reconnection
when its declarative peer list changes, including when enrolling/revoking a
phone; Zeus's configuration is preserved but its connection may briefly reset.

## Validate on Wi-Fi and cellular

- Enable the tunnel; confirm the phone's latest handshake and transfer counters
  with `ssh olympus 'wg show wg0'` (safe; do not use `showconf` or `dump`).
- Open an IP-check site: the public IPv4 should be **37.27.31.37**. Check normal
  browsing and DNS; DNS tests should not show your home/mobile ISP resolver.
- Check IPv6 testing: no direct cellular/Wi-Fi public IPv6 should escape while
  the tunnel is on. IPv6-only connections are intentionally unavailable.
- Try the VPS's port 22/2019 and `10.77.0.2` with a network client: they must be
  unreachable from the phone. `10.77.0.1` ping is intentionally blocked for
  phone peers; use handshake/transfer counters instead.
- Verify Zeus still handshakes and `ping -c 3 10.77.0.1` works from Zeus.
- Test cellular roaming/reconnection, and recheck the public IP after switching
  Wi-Fi off. Do not assume the VPN is always on after app/OS changes.

If browsing fails despite a handshake, check the selected public interface,
Hetzner outbound policy (internet return traffic and DNS), firewall counters and
NAT configuration. Do not disable the firewall or widen server-side AllowedIPs
to `0.0.0.0/0`. Client AllowedIPs are full-tunnel; server-side peer AllowedIPs
must remain each device's exact IPv4/IPv6 addresses.

## Revocation and rekeying

Remove only the device's **public** JSON file, review the diff and deploy Olympus
again. This removes its peer and NAT/forwarding permissions. The old QR/config
will no longer authenticate. Deleting a local QR/config alone does not revoke a
device. Keep a phone's enrollment for one device only; never share profiles.

For a replacement device, revoke first and then create a new enrollment under
a new name. Remove any obsolete private state files locally after deciding
whether they need to be retained; the helper never deletes them automatically.

## Automated checks

```sh
nix build .#checks.x86_64-linux.wireguard-enroll --no-link
nix build .#checks.x86_64-linux.wireguard-mobile --no-link
```

The enrollment check uses temporary throwaway keys, tests restrictive file
permissions, public/private separation, duplicate/address validation and refusal
to send QR secrets to redirected output. No generated keys are copied to test
outputs. The NixOS VM check exercises real NAT/firewall packets using isolated
namespaces representing the decrypted tunnel, internet and home peer. It tests
internet egress, private/management isolation, IPv6 fail-closed behaviour and
firewall restart idempotency. It does not test iOS or replace live checks.
